# 使用说明

`dsh-agent-session-sync` 在 **DeepSeek Harness（DSH）** 与本机第三方 AI 编程 agent 之间**双向导入**对话记录。

两个方向都是主体功能，互相对称——站在哪一边看，都是「把对话导入到这边」：

| 方向 | 做什么 | 面板位置 | 可用对象 |
| --- | --- | --- | --- |
| **导入到 DSH** | 把第三方 agent 的本地历史变成 DSH 会话 | 「导入到 DSH」标签页 | 6 个来源 |
| **导入到其他 agent** | 把 DSH 会话写进本机第三方 agent | 「导入到其他 agent」标签页 | 1 个目标 |

全程只在本机读写，不联网、不上传。

---

## 一、导入到 DSH（第三方 agent → DSH）

### 1.1 支持的来源

| 来源 | 读取位置（只读） | 说明 |
| --- | --- | --- |
| **Codex** | `~/.codex/sessions/**.jsonl` + `~/.codex/thread_history_1.sqlite` | CLI 与桌面版共用同一存储 |
| **Claude Code** | `~/.claude/projects/**.jsonl` | Anthropic 官方 CLI |
| **Cursor IDE** | `~/Library/Application Support/Cursor/.../state.vscdb`（Windows 在 `%APPDATA%\Cursor\...`） | Agent / Composer 对话 |
| **ZCode** | `~/.zcode/cli/db/db.sqlite` | 字节 ZCode CLI |
| **Kimi** | `~/.kimi-code/sessions`（可用 `KIMI_CODE_HOME` 覆盖）+ 桌面端 `conversations.sqlite` | Kimi Code CLI 与桌面端 |
| **WorkBuddy** | `~/.workbuddy/projects/**.jsonl`（可用 `WORKBUDDY_HOME` 覆盖） | 会话内嵌真实 cwd |

来源不可用时左侧会置灰并给出原因（例如「找不到 Claude Code 数据目录」），不影响其他来源。

各来源都会**自动跳过已删除 / 已归档**的对话：
- Codex：以 `state_5.sqlite` 的 `threads.archived` 为准
- ZCode：`session.time_deleted` 非空即隐藏
- Cursor：跳过 `isArchived = 1` 和 `empty-state-*` 占位对话
- WorkBuddy：以 `workbuddy.db` 的 `sessions` 表为准，`deleted_at` 非空或表内无记录都不列出

### 1.2 面板操作

1. 侧边栏点 **会话互导**（Session Transfer）。
2. 左侧 **来源** 选一个 agent。
3. 右侧列表按项目文件夹分组，点标题可展开 / 收起全部。
4. 用 **搜索** 按标题或项目路径过滤；用 **显示范围** 切换：
   - **未导入**：只显示还没导入过的（默认）
   - **全部**：包括已导入的（带「已导入」徽标）
5. 勾选目标对话，或用 **全选未导入** 一次选完。
6. 选 **导入模式**（见 1.3），点 **开始导入**。

导入弹窗会显示总进度、当前正在处理的条目和逐条结果；失败的条目可以 **重试失败项**，中途可 **取消导入**。

### 1.3 两种导入模式

两种模式**内容都不丢**，区别只在结构和续聊兼容性：

| 模式 | 思考 | 工具调用 / 结果 | 适合 |
| --- | --- | --- | --- |
| **完整保真** | 结构化思考块 | 结构化工具卡片 | 只想读、回看历史 |
| **接续友好** | 转为文本 | 转为 `[工具调用]` / `[工具结果]` 文本 | 要在这个会话上**继续对话** |

选择建议：
- 阅后即焚、只想查历史 → 完整保真
- 想在旧会话基础上接着干活 → 接续友好（去掉 tool/thinking 线上结构，任何模型都能安全接续）

> 历史超过约 120 万字符（≈40 万 tokens）且选了完整保真时，结果里会出现一条提示，建议改用接续友好模式——因为大历史续聊会挤占上下文。

### 1.4 导入后归入对应工作区

DSH 的左侧列表是按**工作区**分组的（`$DSH_HOME/storages/workspace.json` 里登记的那些），不是按会话自己的 cwd 分组。导入走的是会话持久化接口，绕过了工作区登记，所以插件会补上这一步：

| 原对话的情况 | 导入后的位置 |
| --- | --- |
| 带真实项目目录（如 `C:\...\WorkBuddy\DeepHarness`） | 归入同名工作区；没有就**新建**一个，标题取目录名（`DeepHarness`） |
| 目录已不存在 / 不是本地绝对路径 / 就是用户主目录 | 不建工作区，落在 **「未分组」** |
| 当前 DSH 组合没有工作区服务 | 会话照常导入，结果里提示「未能归入工作区」 |

结果行会写明去向：`· 已归入工作区「DeepHarness」` / `· 已新建工作区「DeepHarness」` / `· 未分组（原对话没有工作区信息）`。

两点说明：
- 工作区是**复用**的：同一个目录反复导入只会有一个工作区，不会重复创建
- 已经在「未分组」里的老会话不会自己搬家，**重新导入一次**（切到「全部」范围再导入）就会归位

### 1.5 重复导入会合并

同一个来源对话再导入一次，会**合并到上次生成的那个 DSH 会话**里：插件读回原会话的日志，和来源逐回合比对，只把来源**新增**的回合追加到末尾。全程不删东西。

| 情况 | 结果 |
| --- | --- |
| 来源没有新内容 | 一个字都不写，结果行显示 **「已是最新，原会话没有变化」** |
| 来源多了 N 个回合 | 追加这 N 个回合，结果行显示 **「已合并到原会话，续接 N 个回合」** |
| 你在 DSH 里接着聊过 | 你那几轮**原样保留**，新回合接在后面 |
| 原会话正在打开 | **不写入**（运行中的会话会把内存状态刷回磁盘），导入为新会话并提示先关闭 |
| 原会话正在被别人写入 | 不写入，导入为新会话并提示；不会在别人写着的会话上做覆盖 |
| 原会话已被你删掉 | 用同一个会话 id 重新建一份 |
| 宿主后端无法追加 | 兜底整份重写，结果行会写明「已整份重写该会话」 |

要点：
- 合并只追加，所以来源里**改写过**的历史（比如你在来源里编辑了旧消息）不会同步过来——这类情况请删掉 DSH 里的旧会话再导入
- 判断「是不是同一段」看的是用户提问文本，不看回答，所以同一句话问了两次会被当成同一回合
- 想退回旧的「整份覆盖」行为，可在调用接口时传 `options.merge: false`

要重新导入已导入的对话：把 **显示范围** 切到「全部」，选中它，再导入。

### 1.6 导入记录

- 记录文件：`$DSH_HOME/session-import/imported.json`
- 保存每条来源对话对应的 DSH 会话 id、标题、cwd、模式、导入时间
- 删除这个文件只重置「已导入」标记，**不会删除会话本身**
- 卸载插件也不会删除已导入的会话

## 二、导入到其他 agent（DSH → 第三方 agent）

### 2.1 支持的目标 agent

| 目标 | 写入位置 | 状态 |
| --- | --- | --- |
| **WorkBuddy** | `~/.workbuddy/projects/<项目>/<uuid>.jsonl` + `workbuddy.db` 的 `sessions` 表 | 可用 |

其他 agent（Claude Code / Codex / Cursor / ZCode / Kimi）目前只支持「导入到 DSH」这一个方向，反向尚未实现——它们在目标列表里不会出现（缺 `write` 会被安全跳过），不会误报成可用。

### 2.2 操作流程（一步写入，写入内容自动核对）

1. 面板顶部切到 **导入到其他 agent** 标签页。
2. 左栏选要导入的 **DSH 会话**（可搜索标题或路径，单条选择）。
3. 右栏选 **目标 agent**。
4. 选 **内容形式**：
   - **完整保真**：保留工具调用与结果卡片
   - **纯文本**：把工具调用和结果写成正文，任何模型都能接续
5. 下方会**自动**出现这次要写什么：会话标题、写入行数与消息数、目标文件路径、**将新建还是会更新已有那条**、原文件的备份位置。
6. 点 **导出到 WorkBuddy**，一步写入。

不需要先点「预览」：计划是（会话 + 目标 + 内容形式）的纯函数，面板在你选好之后自己去取，结果就摆在同一屏上。安全底线没有放松，反而更严——只有**当前这组设置**的计划已经在屏幕上时，写入按钮才会亮；改了会话、目标或内容形式，按钮立刻变灰，直到新的计划到达。

**不存在就新建，存在就更新那一条**，没有第三种情况，所以也不需要你勾选「允许覆盖」：目标 id 由源会话 id 派生，系统已经知道这条会话在不在。更新前会自动备份原文件，备份路径写在结果里。

### 2.3 左栏只列「页面上看得见的会话」

左栏的来源是 DSH 页面自己的会话列表（`ctx.sessions.list`），不是磁盘目录扫描。因此：

- **只列页面上有的会话**：别的 workspace 里没在当前页面出现的、以及被页面隐藏的会话不会混进来
- **不列子 agent 会话**：`[dsh-*:delegated]` 这类子会话只能在父会话里进入，页面上没有独立条目，也就不在左栏
- **不列空白会话**：还没发过任何消息的会话没有可导入内容，以前会出现在左栏、点了「开始导入」才报错，现在直接不列
- **面板开着时会自动跟着变**：新建或删掉会话后左栏自动更新，不用刷新
- 标题下方会显示一行小字：`只列出页面上的 N 个会话（本机共 M 个）`

如果这个 DSH 版本没有会话列表服务（极少见），左栏会退回「列出本机全部会话」，并显示 `未能读取页面会话列表`。

### 2.4 同一条 DSH 会话再次导入会更新，而不是再复制一份

导出目标里的会话 id 取自 **DSH 会话自己的 id**（原生会话是裸 UUID，本插件导入过的会话是 `session-<uuid>`，去掉前缀后同样可用）。所以只有一个落点：

| WorkBuddy 里的状态 | 这次导出做 |
| --- | --- |
| 没有这条会话 | 新建（徽标 `将新建会话`） |
| 已有这条会话 | **原地更新**那一条，写入前备份原文件（徽标 `将更新已有会话`） |

- 不会出现「导了三次，WorkBuddy 里三条同名会话」的情况
- 更新不需要额外确认：计划卡片已经写明这次是更新，备份路径在写入后显示出来
- 来源会话 id 不是 UUID 时（例如从别处导入的、id 形如 `session-dry` 的会话）没有可复用的稳定 id，会生成一个新的 UUID（这种情况每次导出都会新建一条）

### 2.5 安全约束

- **确认后才写**：只有当前设置的计划已经显示在屏幕上，写入按钮才可用
- **存在即更新、缺则新建**：同一源会话只有一个落点，不会越导越多
- **覆盖前备份**：transcript 与 `workbuddy.db` 都会先备份，路径显示在结果里
- **目标应用运行中拒绝写入**：WorkBuddy 开着时会拒绝，因为它持有会话状态，下次保存会覆盖掉外部写入
- **原子写入**：临时文件 + fsync + rename，中途失败不会留下半个文件
- **目标没有会话索引时自动创建**：首次导入会建最小表结构，让会话能出现在 WorkBuddy 侧边栏

### 2.6 导入后在 WorkBuddy 里看到

导入过去的会话写入 WorkBuddy 的 `projects/` 目录并注册到索引表，启动 WorkBuddy 后应出现在对应项目分组下。

如果机器上从未运行过 WorkBuddy，索引库不存在，导入时会自动创建——但更稳妥的做法是**先启动一次 WorkBuddy**，让它建好自己的完整结构。

## 三、常见问题

**Q：导入后左侧列表没看到新会话？**
刷新页面。导入时会把标题写进投影缓存，正常情况下不用手动刷新。

**Q：为什么「未导入」范围下看不到某条对话？**
它之前导入过。切到「全部」就能看到，并带「已导入」徽标。

**Q：导入的会话能继续聊天吗？**
能，但建议用「接续友好」模式导入。完整保真模式保留了历史工具调用和思考结构，部分模型 API 会校验这些内容而拒绝请求。

**Q：能把 DSH 会话导入到 Cursor / Codex / Claude Code 吗？**
当前不行，只有 WorkBuddy 实现了这个方向。架构是插拔的，加一个 sink 文件即可支持，见 `docs/adding-sink.md`。

**Q：重复导入会不会覆盖我在 DSH 里聊过的内容？**
不会。重复导入是追加式合并，只把来源新增的回合接在原会话末尾，你在 DSH 里的本地对话原样保留。来源没有新内容时不会写入任何东西。

**Q：导入到其他 agent 会改动 DSH 里的原会话吗？**
不会。这个方向只读 DSH 会话，写入的是目标 agent 的文件。

**Q：导入到其他 agent 为什么不用先点「预览」了？**
计划是（会话 + 目标 + 内容形式）算出来的，不需要用户再按一次按钮去取。现在它自动出现，写入按钮只在**当前这组设置**的计划已经在屏幕上时才可用——安全底线是「写之前你看过要写什么」，不是「你点过两次」。

**Q：同一条 DSH 会话导入到 WorkBuddy 两次，会有两条吗？**
不会，是更新同一条。导出用的是源会话自己的 id（`session-<uuid>` 会去掉前缀），所以第二次落盘会原地更新那一条，原文件先备份。计划卡片会提前标 `将更新已有会话`。

**Q：左栏为什么比 DSH 页面上的会话少？**
左栏只列页面上的会话，且去掉子 agent 会话和空白会话。标题下面那行小字会写清楚：`只列出页面上的 N 个会话（本机共 M 个）`。

**Q：插件会读我的云端账号吗？**
不会。所有来源都是本机磁盘上的本地历史文件，全程无网络请求。

## 四、重置与卸载

| 想做什么 | 怎么做 |
| --- | --- |
| 重置「已导入」标记 | 删除 `$DSH_HOME/session-import/imported.json` |
| 删除某个导入的会话 | 在 DSH 会话列表里正常删除 |
| 卸载插件 | Plugins → 该插件 → Uninstall（不删已导入的会话） |
| 关闭导入说明文字 | 写入会话时传 `importNotice: false`（面板默认开启） |

## 五、给开发者

- 新增来源（导入到 DSH）：`docs/adding-provider.md`
- 新增目标 agent（导入到第三方）：`docs/adding-sink.md`
- WorkBuddy JSONL 事件格式：`docs/workbuddy-format.md`
- 端点协议：`POST /session-import/<list|import|status|cancel>`、`POST /session-export/<sources|targets|export>`
  - `sources` 接受 `{ ids?: string[] }`：给了 `ids` 就只返回这些会话（面板传的就是页面上的会话 id），返回 `{ conversations, pageOnly, total, hidden }`；不传则返回本机全部
